Today, I'm proud to announce Homebrew 7.0.0.
The most significant changes since 6.0.0 are built-in vulnerability checks, stronger sandboxing, smoother installations and upgrades, faster commands, improved support for bottles outside the default prefix and changes to macOS support.

### ✨ Highlights since 6.0.0

#### 🔍 Built-in vulnerability checks

[`brew vulns` is a built-in command](https://github.com/Homebrew/brew/pull/23080), bringing the vulnerability scanner introduced as a separate tap in 6.0.0 into Homebrew itself.
It checks formulae for known security vulnerabilities using OSV.dev, helping identify software that needs attention without installing another tap or gem.

- [`brew vulns` checks installed formulae by default and reports when an untrusted tap prevents a scan, making gaps in the results visible.](https://github.com/Homebrew/brew/pull/23140)
- [`brew vulns --severity=high` focuses on higher-severity findings, while `--deps` and `--brewfile` help check a project's dependencies.](https://github.com/Homebrew/brew/pull/23080)
- `brew vulns` helps prioritise fixes with [`--fix-available` and `--no-fix-available`](https://github.com/Homebrew/brew/pull/23152), plus [`--fix-type` to distinguish released fixes from unreleased patches and `--list-skipped` to show formulae it could not check](https://github.com/Homebrew/brew/pull/23511).
- [Homebrew formulae can identify security fixes in their patches with `resolves`, allowing vulnerability checks to recognise fixes already included in a Homebrew package.](https://github.com/Homebrew/brew/pull/22466)

#### 🐧 Stronger sandboxing

Homebrew [replaces the Linux Bubblewrap sandbox with Landlock](https://github.com/Homebrew/brew/pull/23425), which needs no separate executable, package installation or `sysctl` configuration.
The Linux sandbox [supports Landlock ABI 2, including environments such as Amazon Fargate with Linux 6.1, and warns when the available kernel cannot enforce network restrictions](https://github.com/Homebrew/brew/pull/23335).

- [Homebrew expanded sandbox restrictions to cover the home directory before refining the protected-path list, establishing broader protection for personal files and credentials.](https://github.com/Homebrew/brew/pull/22660)
- Homebrew applies sandbox restrictions to [formula install steps](https://github.com/Homebrew/brew/pull/23202) and [structured cask operations and generated completions](https://github.com/Homebrew/brew/pull/23461), protecting more of the installation process.
- [Homebrew formulae can define a separate `fetch` phase to download language dependencies before an offline `install` phase, making source builds easier to reproduce and limiting network access during compilation.](https://github.com/Homebrew/brew/pull/23657)
- [Homebrew gives more language package managers persistent download caches and isolates caches that do not verify their contents in CI, reducing repeated downloads and the risk of one build affecting another.](https://github.com/Homebrew/brew/pull/23656)
- [Homebrew adds a Landlock sandbox for Linux, providing the foundation for isolation that works without Bubblewrap's container setup requirements.](https://github.com/Homebrew/brew/pull/23255)
- [Homebrew introduced `brew setup-sandbox` to configure the earlier Bubblewrap backend, a setup command superseded by the switch to Landlock.](https://github.com/Homebrew/brew/pull/22691)
- [Homebrew allowed the earlier Bubblewrap backend to install automatically during source builds, removing a setup failure before Landlock replaced that backend.](https://github.com/Homebrew/brew/pull/22728)
- [Homebrew's Landlock sandbox permits standard device and inter-process communication operations, allowing builds to use terminals and shared memory.](https://github.com/Homebrew/brew/pull/23288)
- [Homebrew's Landlock sandbox supports pseudo-terminals, allowing build and test tools that spawn interactive processes to work.](https://github.com/Homebrew/brew/pull/23279)
- [Homebrew cask `run` steps can explicitly request network access for upstream setup tasks while other steps retain network restrictions.](https://github.com/Homebrew/brew/pull/23497)
- [Homebrew improved the earlier Bubblewrap backend's container support so Linux CI could exercise sandbox restrictions before the move to Landlock.](https://github.com/Homebrew/brew/pull/22907)
- [Homebrew provides a restricted opt-in for avoiding nested sandboxing, allowing isolated development environments to test commands that would otherwise hang or fail.](https://github.com/Homebrew/brew/pull/22793)
- [Homebrew restores explicitly privileged cask installation steps, allowing applications such as Parallels to complete setup after structured operations gained sandboxing.](https://github.com/Homebrew/brew/pull/23476)
- [Homebrew makes tap trust records readable inside build sandboxes, preventing trusted third-party formulae from failing when their definitions are reloaded.](https://github.com/Homebrew/brew/pull/22751)
- [Homebrew handles home-directory symlinks without blocking their external targets, keeping devices such as `/dev/null` usable inside the sandbox.](https://github.com/Homebrew/brew/pull/23161)
- [Homebrew keeps sandboxed tools away from inaccessible user configuration files, preventing Git and other build tools from failing on denied reads.](https://github.com/Homebrew/brew/pull/22712)
- [Homebrew tolerates readable paths disappearing during Landlock setup, avoiding failures caused by a filesystem race.](https://github.com/Homebrew/brew/pull/23541)
- [Homebrew keeps tap remotes available inside build sandboxes, allowing trust checks to work without reading inaccessible global Git configuration.](https://github.com/Homebrew/brew/pull/22721)
- [Homebrew narrows home-directory deny rules to sensitive paths, retaining credential protection while avoiding expensive recursive scans of large home directories.](https://github.com/Homebrew/brew/pull/22715)
- [Homebrew treats explicitly allowed network phases as an exclusive list, letting formulae grant access only where downloads are required.](https://github.com/Homebrew/brew/pull/23635)
- [Homebrew's earlier Bubblewrap setup tolerated missing or unwritable kernel settings, avoiding probe failures before Landlock replaced that backend.](https://github.com/Homebrew/brew/pull/23015)
- [Homebrew allows POSIX message-queue reads under the appropriate Landlock profiles, keeping sandboxed `glibc` tests functional.](https://github.com/Homebrew/brew/pull/23302)
- [Homebrew warns when required build paths keep part of a protected home-directory location readable, making exceptions to sandbox protection visible.](https://github.com/Homebrew/brew/pull/23256)
- [Homebrew corrected duplicate Bubblewrap installation and missing sandbox activation in the earlier Linux sandbox, restoring affected installations before the move to Landlock.](https://github.com/Homebrew/brew/pull/22669)
- [Homebrew falls back to generic CPU detection when macOS blocks `sysctl`, preventing sandboxed commands from misidentifying the architecture.](https://github.com/Homebrew/brew/pull/22682)
- [Homebrew permits the specific temporary cache files required by `xcrun`, avoiding compiler errors during sandboxed dependency fetching.](https://github.com/Homebrew/brew/pull/23748)
- [Homebrew accepts ordinary punctuation in protected home-directory paths and keeps tap trust readable, fixing source installations blocked by the earlier home sandbox rules.](https://github.com/Homebrew/brew/pull/22700)
- [Homebrew preserves normal terminal line endings during sandboxed keyboard input, keeping piped installation logs from appearing diagonally across the terminal.](https://github.com/Homebrew/brew/pull/23514)
- [Homebrew blocks sandboxed reads of common shell startup files, reducing exposure of credentials stored alongside shell configuration.](https://github.com/Homebrew/brew/pull/22716)

#### 📦 Smoother installations and upgrades

- `brew install`, `brew reinstall` and `brew upgrade` share downloads across formulae and casks and defer cleanup until the end, reducing interruptions between packages during [installation](https://github.com/Homebrew/brew/pull/23549), [reinstallation](https://github.com/Homebrew/brew/pull/23550) and [upgrades](https://github.com/Homebrew/brew/pull/23551).
- [`brew install`, `brew reinstall` and `brew upgrade` continue with other packages after individual download or bottle extraction failures, while reporting the failure in the final exit status.](https://github.com/Homebrew/brew/pull/23525)
- [`brew bundle` batches ordinary formula installations and upgrades into shared `brew` invocations, avoiding conflicts when several Brewfile entries need the same dependency.](https://github.com/Homebrew/brew/pull/23659)
- [`brew upgrade` distinguishes requested packages from dependencies and dependants in its preview, making the reason for additional upgrades clearer.](https://github.com/Homebrew/brew/pull/23691)
- [`brew upgrade` reports when an automatic dependant upgrade proves unnecessary and includes only successful upgrades in its final summary.](https://github.com/Homebrew/brew/pull/23491)
- [Homebrew collects caveats into one summary after cleanup so installation advice is easier to find.](https://github.com/Homebrew/brew/pull/23552)
- [`brew reinstall` keeps the existing package linked until execution begins and restores links after failure, avoiding broken paths during planning and misleading analytics errors.](https://github.com/Homebrew/brew/pull/22994)
- [Homebrew handles same-name cask-to-formula migrations without taking the formula lock twice, allowing upgrades and reinstalls to finish.](https://github.com/Homebrew/brew/pull/22955)
- [Homebrew checks pinned implicit dependencies before installation, preventing an upgrade plan from promising changes that cannot succeed.](https://github.com/Homebrew/brew/pull/23090)
- [Homebrew passes the upgrade download queue directly to installers, avoiding an unused thread pool and shutdown failures in tests.](https://github.com/Homebrew/brew/pull/23416)
- [Homebrew prepares cask dependencies and groups successful package cleanup, laying the groundwork for more efficient batch installations.](https://github.com/Homebrew/brew/pull/23547)
- [Homebrew retains successful upgrades and shared download plans for final reporting, avoiding duplicate package summaries during combined upgrades.](https://github.com/Homebrew/brew/pull/23548)
- [`brew upgrade` includes only successful formula and cask upgrades in its final summary, accurately reporting partial failures.](https://github.com/Homebrew/brew/pull/22702)
- [Homebrew recognises dependency aliases in older installation receipts, avoiding false missing-dependency errors after package renames.](https://github.com/Homebrew/brew/pull/22714)
- [Homebrew creates a formula's stable `opt` link even when prefix linking is disabled, allowing unlinked Brewfile packages and their dependants to work correctly.](https://github.com/Homebrew/brew/pull/22783)
- [Homebrew skips linking conflicts when a formula will remain unlinked, allowing otherwise conflicting packages to be installed as dependencies.](https://github.com/Homebrew/brew/pull/22766)
- [Homebrew isolates errors while preparing individual package downloads, allowing other installations to proceed while returning a failure status for the affected package.](https://github.com/Homebrew/brew/pull/23385)
- [Homebrew creates a shared PowerShell completion directory, preventing one formula's completions from being written inside another formula's installation.](https://github.com/Homebrew/brew/pull/23537)
- [Homebrew removes all obsolete name links for an uninstalled keg, avoiding stale aliases when several versions share a package directory.](https://github.com/Homebrew/brew/pull/23753)
- [Homebrew looks up core formula names directly and avoids redundant filesystem checks, shortening installation and upgrade planning.](https://github.com/Homebrew/brew/pull/22977)

#### 🏎️ Performance

- `brew install` [starts downloads while local checks are still running](https://github.com/Homebrew/brew/pull/23381) and [loads full installers only when needed](https://github.com/Homebrew/brew/pull/23560), shortening the wait before useful work begins.
- [`brew cleanup` avoids repeatedly scanning the entire cache for each installed formula, making cleanup substantially faster on systems with many packages.](https://github.com/Homebrew/brew/pull/23515)
- [`brew update` prepares Ruby caches in the background after updates to vendored dependencies, reducing startup work for the next installation or upgrade.](https://github.com/Homebrew/brew/pull/23108)
- `brew config` [gathers system details concurrently](https://github.com/Homebrew/brew/pull/22989) and `brew tap-info` [gathers installed tap details concurrently](https://github.com/Homebrew/brew/pull/22975), producing diagnostics sooner.
- Homebrew [starts common commands with fewer subprocesses](https://github.com/Homebrew/brew/pull/23298) and [reuses cached API data more efficiently while still checking its signature](https://github.com/Homebrew/brew/pull/23300), reducing overhead on repeated runs.
- [Homebrew skips loading cask support for commands such as `brew leaves`, `brew missing` and `brew doctor` when no casks are installed.](https://github.com/Homebrew/brew/pull/23798)

#### 🍎 macOS support

The macOS changes announced in earlier releases have reached their next stage:

- [Homebrew classifies Intel Macs as Tier 3, reflecting the end of routine Intel bottle builds and full CI coverage.](https://github.com/Homebrew/brew/pull/23679)
- [Homebrew keeps existing Intel bottles installable, but new or updated formulae without a suitable bottle build from source.](https://github.com/Homebrew/brew/pull/23677)
- [Homebrew requires macOS Big Sur 11 or later to run, so macOS Catalina 10.15 and earlier need an operating system upgrade or another package manager.](https://github.com/Homebrew/brew/pull/23703)
- [Homebrew's macOS `.pkg` installer is Apple Silicon only, preventing new package-installer deployments onto Intel systems with Tier 3 support.](https://github.com/Homebrew/brew/pull/23779)
- [`brew doctor` bases migration advice on the availability of binary packages, explaining that existing Homebrew bottles may remain useful on Intel Tahoe where MacPorts also lacks a full set of binary packages.](https://github.com/Homebrew/brew/pull/23806)

#### 🍾 Bottles outside the default prefix

Homebrew [can install more bottles at prefixes no longer than the prefix where they were built](https://github.com/Homebrew/brew/pull/23699), reducing the need for slower source builds in custom installations.
This is an incremental improvement: it does not make every bottle relocatable or change the support tier of a custom installation.

- [Homebrew checks the active structure of Linux binaries when deciding whether a bottle can be relocated, avoiding unnecessary source builds caused by unused build-path strings.](https://github.com/Homebrew/brew/pull/23644)
- [Homebrew adjusts symlinks that point into the original installation prefix, keeping them usable when a bottle is installed elsewhere.](https://github.com/Homebrew/brew/pull/23682)
- [Homebrew records longer bottle build prefixes in metadata, preparing compatible installations to reuse these bottles without falling back to source builds.](https://github.com/Homebrew/brew/pull/23693)
- [Homebrew documents a staged plan for broader bottle relocation, prioritising faster installations and fewer source builds before expanding supported prefix lengths.](https://github.com/Homebrew/brew/pull/23605)
- [Homebrew checks raw macOS library linkage when classifying bottles, avoiding unnecessary source builds caused by resolving already-relocatable paths.](https://github.com/Homebrew/brew/pull/23646)
- [Homebrew schedules the full relocated-bottle validation sweep after package fixes, ensuring the planned catalogue check measures the completed migration.](https://github.com/Homebrew/brew/pull/23681)
- [Homebrew removes unused Node build files and strips native add-ons when bottling, reducing embedded build paths that prevent relocation.](https://github.com/Homebrew/brew/pull/23645)
- [Homebrew relocates bottles using recorded file lists and combines binary edits, reducing full-package scans and repeated rewriting during installation.](https://github.com/Homebrew/brew/pull/23643)
- [Homebrew strengthens bottle relocation around hardlinks, prefix lengths and embedded loader references, helping packages remain runnable after installation at another prefix.](https://github.com/Homebrew/brew/pull/23667)
- [Homebrew completes further bottle-relocation hardening, preserving linked file identities and rejecting unsupported prefix lengths before files are modified.](https://github.com/Homebrew/brew/pull/23670)
- [Homebrew records relocation work when bottles are built, allowing installations to reuse file lists instead of rediscovering them on every machine.](https://github.com/Homebrew/brew/pull/23629)
- [Homebrew avoids rewriting or re-signing Mach-O binaries when no runtime search path changes, reducing unnecessary disk work during relocation.](https://github.com/Homebrew/brew/pull/23079)
- [Homebrew skips incompatible ELF rewriting for Bun binaries, preventing bottle processing from producing executables that no longer run.](https://github.com/Homebrew/brew/pull/23589)

### 🔮 Upcoming changes

- [Homebrew plans to stop running on Intel Macs and macOS Big Sur on Apple Silicon in or after September 2027, continuing the published macOS support timeline.](https://docs.brew.sh/Support-Tiers#future-macos-support)
- [Homebrew is testing bottles built with longer prefixes before a broader rollout, with a multi-month trial before extending relocation support to longer custom installation paths.](https://github.com/Homebrew/brew/pull/23699)

### 🔒 Security

- [Homebrew uses signed API metadata for package operations, including recovering cask uninstall instructions, so unsigned package responses cannot determine which commands run or files are removed.](https://github.com/Homebrew/brew/pull/23772)
- [`brew update` requires an automatic tap migration's destination to be trusted before installing it, preventing a third-party tap from silently authorising a different package.](https://github.com/Homebrew/brew/pull/23662)
- [Homebrew rechecks tap allow and forbid lists after Git redirects, preventing a server from moving a tap outside the configured restrictions.](https://github.com/Homebrew/brew/pull/22909)
- [Homebrew checks the files a patch will modify before applying it, rejecting paths outside the staged source tree while allowing valid upstream patches.](https://github.com/Homebrew/brew/pull/22908)

- [Homebrew's macOS installer resets Git configuration before privileged operations so configuration controlled by the installation user cannot run commands as root.](https://github.com/Homebrew/brew/pull/23747)
- [`brew mcp-server` rejects inline cask definitions supplied as package names, preventing a lookup request from being interpreted as Ruby code.](https://github.com/Homebrew/brew/pull/22875)
- [`brew bump-formula-pr` and `brew bump-cask-pr` redact GitHub credentials from dry-run output, keeping tokens out of terminal and CI logs.](https://github.com/Homebrew/brew/pull/22874)
- [`brew livecheck` rejects HTTPS-to-HTTP redirects by default, protecting version checks from an insecure connection downgrade.](https://github.com/Homebrew/brew/pull/22944)
- [Homebrew can verify bottle attestations from supported third-party taps, extending checks on where binary packages were built beyond `homebrew/core`.](https://github.com/Homebrew/brew/pull/23769)

- [Homebrew validates cask artifact dispatch, resolves trust through symlinks and hardens installer paths and terminal output, reducing the influence of untrusted metadata on privileged operations.](https://github.com/Homebrew/brew/pull/23720)

- [`brew vulns` recognises security fixes declared in API-provided formula patches, avoiding reports for vulnerabilities Homebrew has already patched.](https://github.com/Homebrew/brew/pull/23114)

### 🗑️ Deprecations

- [`brew bundle --jobs` is deprecated and ignored because formula installations use batching, with download concurrency controlled by `HOMEBREW_DOWNLOAD_CONCURRENCY`.](https://github.com/Homebrew/brew/pull/23659)
- [Homebrew disables previously deprecated settings including `HOMEBREW_BUNDLE_JOBS`, `HOMEBREW_BUNDLE_NO_JOBS`, `HOMEBREW_USE_INTERNAL_API` and `HOMEBREW_SANDBOX_LINUX`, so shell and CI configuration should stop explicitly enabling behaviours that are defaults.](https://github.com/Homebrew/brew/pull/23729)
- [Homebrew deprecates `HOMEBREW_NO_REQUIRE_TAP_TRUST` and `HOMEBREW_NO_SANDBOX_LINUX`, directing configurations towards explicit `brew trust` decisions and a Landlock-enabled Linux kernel.](https://github.com/Homebrew/brew/pull/23729)
- [Homebrew deprecates legacy formula `post_install` and cask flight hooks in third-party taps in favour of structured install steps, providing a migration path towards sandboxed, API-backed installation.](https://github.com/Homebrew/brew/pull/23729)
- [Homebrew deprecates the cask URL `verified:` parameter, which no longer contributes to URL verification.](https://github.com/Homebrew/brew/pull/23729)
- [`brew vulns --json` returns an object containing `findings` and `skipped_formulae` instead of a top-level array, so scripts can distinguish reported vulnerabilities from gaps in scan coverage.](https://github.com/Homebrew/brew/pull/23511)
- [Homebrew stops synchronising Homebrew/brew's legacy `master` branch, so integrations tracking development should use `main`.](https://github.com/Homebrew/brew/pull/23732)
